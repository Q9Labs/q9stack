# Convex diagnostics recipe

## Problem and reference

Give a support agent a retrievable, redacted browser-to-server failure journey from one code, without making that code an ingestion capability or copying private causes into durable events. This is product-owned code, not a shared Convex runtime package. Reference implementations: `recruiter/packages/convex/convex/diagnostics/{schema,mutations,maintenance,credentials}.ts`, `recruiter/packages/convex/convex/{schema,crons}.ts`, `recruiter/packages/convex/convex/platform/{functions,errors}.ts`, `recruiter/apps/portal/src/lib/diagnostics/{core,reporter,convex-client}.ts`, and `recruiter/apps/studio/src/lib/diagnostics.ts`. Link this recipe from the adopting product's `AGENTS.md`.

## Product implementation

1. Add `@q9labsai/diagnostics`. Keep one `journeyTraceId` per browser tab, mint a distinct `createDiagnosticCode()` for an unexpected failure or manual report, and link the event to the journey. Prefer a server-returned code. Display it only after the server created or authorized queued event can be retrieved. Capture navigation, request timing, Convex operation and function name, errors and optional replay session using `sanitizeDiagnosticEvent` before a bounded independent delivery queue. Use product-owned route templates; do not send query strings, raw paths with identifiers, headers, bodies, form values, names, emails, transcripts, tokens, object keys, raw Error messages, or full stacks. Diagnostics delivery must never fail an application operation. Set `requestId` only to an ID the server returned; never mint one in the browser, because `q9 diag` joins it against Convex's own request IDs. Without it, `q9 diag` matches server executions by function name and time and marks them `heuristic`.
2. Add `diagnosticEvents` to the product's Convex schema. Store the `DiagnosticEvent/v1` envelope plus server-derived `receivedAt`, `subjectId`, source surface, and the tenant/organization when the report has server-verified tenant context (never a browser assertion). Index `(traceId, occurredAt)`, `(traceId, eventId)` for deduplication, `(journeyTraceId, occurredAt)`, `(flow_run, occurredAt)` as `by_flow_run`, `(subjectId, receivedAt)` for quota, and `(receivedAt)` for cleanup. Keep 14 days **from receipt**. Store only sanitized frame locations (file, line, column, function), never server exception text or cause.
3. Implement authenticated `diagnostics:ingest`: verify the user's session, derive subject/tenant server-side, reject client-provided identity/receipt/deployment, validate events again with `diagnosticEventSchema`, and reject forged trace links. An anonymous candidate flow needs its own server-minted scoped high-entropy capability, stored as a hash and bound to the correct application/interview. A diagnostic code alone authorizes nothing. Enforce at most 20 events per batch, 2048 bytes per event, bounded field and batch size, ±7-day clock skew, idempotent `(traceId,eventId)` inserts, and rolling per-session/subject request and event budgets (candidate default at most 500 accepted events/24 h). Reject excess with a safe error.
4. Implement the internal read-only `diagnostics/lookup:trace` query taking one object with optional `traceId` (DiagnosticCode/v1) and `flowRun` (string), rejecting calls that set both or neither. Convex and Confect require a top-level object, so a union of two objects fails to register and returning `{ events: DiagnosticEvent/v1[], expired?: boolean }`. Authorization is independent of code or run ID knowledge. Trace lookup includes linked journey events when authorized. Run lookup uses `by_flow_run` and returns all retained events across traces for that run. Order by `occurredAt`; report truncation/missing evidence to operators. It must return an empty list for an unknown valid code or run ID. Never expose raw causes or credentials. Record flow steps as ordinary events with `flow`, `flow_run`, `flow_step`, and branch `outcome`; see [the flows recipe](diagnostics-flows.md).
5. Add a daily cron calling an internal cleanup mutation: query the `receivedAt` index, delete at most 500 expired rows, and reschedule when full. Do not scan the whole table.
6. If the product has a central function wrapper (Effect or otherwise), wrap its `INTERNAL` boundary: catch unexpected Effect fiber defects only, log `convex.function.failed` with trace ID and full cause to privileged Convex logs, persist only safe span metadata and optional sanitized frame locations, and return safe `INTERNAL` plus code. Pass expected validation/auth/not-found/billing errors unchanged. `q9 diag` links any server log line that contains the trace ID (`trace_id` correlation), so logging it is what joins the server cause to the code. Products without a central wrapper skip this step and rely on request-ID and heuristic matching.
7. If PostHog runs, attach `diagnostic_trace_id` to events (journey ID ordinarily, displayed code for a failure/report); attach `journey_trace_id` separately when different. Record only a validated opaque replay-session ID as a diagnostic link. Diagnostics must work without PostHog.
8. Add `"diag": "q9 diag"` to `package.json` and `q9.config.json` with, for example, `"diag": { "adapter": "convex", "convexDir": "packages/convex", "lookup": "diagnostics/lookup:trace" }`. Install the Convex CLI in that workspace. `pnpm diag check` probes read access without reading customer data; development is the default and `--prod` is explicit.

## Conformance check

In a test deployment, validate the package's `fixtures/redaction-corpus.v1.json` at browser and ingest boundaries; reject forged identity/capability and unsafe IDs; ingest the valid-event fixture twice and prove deduplication; retrieve it with `pnpm diag trace <code> --json`; prove a known missing code reports `not_found`, missing server log reports `server_log_not_available`, and a receipt older than 14 days is deleted/reported `expired`. Confirm neither event storage nor CLI output contains the forbidden corpus. Verify authenticated Portal failure and authorized Studio failure/manual report are retrievable, and queue outage does not break the primary flow.
